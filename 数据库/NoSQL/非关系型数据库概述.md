# 非关系型数据库概述
非关系型数据库（Non-Relational Database），通常被称为 NoSQL（意为 Not Only
SQL），是一类区别于传统关系型数据库（RDBMS）的数据管理系统的统称。

随着互联网时代海量数据（Big Data）、高并发读写、高可用性以及灵活数据结构需求的爆发，非关系型数据库应运而生。它放弃了传统关系型数据库严格的关系模型和部分
ACID 事务约束，以换取极高的横向扩展能力和读写性能。

一、 核心特点与设计理念

1.  去中心化模式（Schema-Free / 弱模式）
      - 不需要预先定义严格的表结构（Schema），字段可以动态增减，支持半结构化（如 JSON、XML）或非结构化数据。
2.  高并发与高性能
      - 去掉了多表关联（JOIN）等复杂计算，许多类型直接利用内存操作或高度优化的数据存储格式，读写吞吐量远超传统数据库。
3.  出色的横向扩展性（Scale-out）
      - 天然支持分布式部署，能够通过增加廉价的服务器节点来分担负载和扩展存储容量，克服单机瓶颈。
4.  灵活的一致性模型
      - 大多数 NoSQL 系统在 CAP 定理中放弃了强一致性（Consistency），遵循 BASE
        理论（基本可用、软状态、最终一致性），优先保障高可用性与分区容错性。

二、 理论基础：CAP 与 BASE

  - CAP 定理：在分布式系统中，一致性（Consistency）、可用性（Availability）、分区容错性（Partition Tolerance）
    三者不可兼得，通常只能在 P 的前提下在 C 和 A 之间权衡：
      - CP 系统：优先保证数据一致性（如 HBase、MongoDB 某些配置）。
      - AP 系统：优先保证系统可用性，容忍短时间内数据不一致（如 Cassandra、DynamoDB）。
  - BASE 理论：
      - Basically Available（基本可用）：出现故障时，允许损失部分可用性或响应变慢。
      - Soft State（软状态）：允许系统中存在中间状态，不影响整体可用。
      - Eventually Consistent（最终一致性）：经过一段时间同步后，所有副本最终达到一致。

三、 四大主要分类及代表产品

根据数据模型和存储结构的不同，NoSQL 数据库通常分为以下四大经典类型，近年来还衍生出专门的向量数据库：

| 分类                              | 核心数据模型                | 代表产品                                           | 优势特点                    | 典型应用场景                     |
| :------------------------------ | :-------------------- | :--------------------------------------------- | :---------------------- | :------------------------- |
| **键值存储**<br>(Key-Value)         | 简单的 `Key-Value` 映射    | **Redis**, Memcached, RocksDB, AWS DynamoDB    | 读写极快、结构简单、内存占用低         | 缓存系统、分布式 Session、计数器、排行榜   |
| **文档型数据库**<br>(Document-Store)  | 树状或键值对文档（如 BSON、JSON） | **MongoDB**, CouchDB, Elasticsearch (常作检索)     | Schema 自由、支持复杂嵌套查询、开发友好 | 内容管理系统 (CMS)、电商商品详情、用户配置画像 |
| **列族/列式数据库**<br>(Column-Family) | 按列族/列组织存储             | **Apache Cassandra**, HBase, ClickHouse (OLAP) | 高写入吞吐、高压缩率、海量数据横向扩展     | 海量日志存储、时序/物联网监控数据、大数据分析    |
| **图数据库**<br>(Graph Database)    | 节点（Node）、边（Edge）及其属性  | **Neo4j**, NebulaGraph, JanusGraph             | 高效处理深度关系遍历，无需多次 JOIN    | 社交网络关系、知识图谱、金融反欺诈、推荐算法     |
| *(新兴) **向量数据库***<br>(Vector DB) | 高维向量嵌入（Embeddings）    | **Milvus**, Pinecone, Chroma, Qdrant           | 高维向量相似度近似检索（ANN）        | 大模型 RAG（检索增强生成）、图像/语音语义搜索  |

四、 关系型数据库 vs 非关系型数据库

| 维度       | 关系型数据库 (RDBMS)                        | 非关系型数据库 (NoSQL)                  |
| :------- | :------------------------------------ | :------------------------------- |
| **代表产品** | MySQL, PostgreSQL, Oracle, SQL Server | Redis, MongoDB, Cassandra, Neo4j |
| **数据模型** | 严谨的二维表结构（行与列）                         | 键值、文档、列族、图等多种形式                  |
| **数据约束** | 强 Schema、主外键、严格数据类型                   | 动态/无 Schema，格式灵活                 |
| **事务支持** | 强 **ACID** 事务，保障强一致性                  | 多数遵循 **BASE** 理论，保障最终一致性         |
| **扩展方式** | 纵向扩展为主（Scale-up，升级 CPU/内存）            | 横向扩展为主（Scale-out，增加机器节点）         |
| **查询语言** | 标准化结构化查询语言（SQL）                       | 无统一标准，通常提供 API 或特定查询语法           |
| **核心优势** | 数据一致性高、支持复杂关联查询                       | 高吞吐、海量存储、水平扩展强、开发迭代快             |

五、 选型与应用建议

在现代系统架构中，NoSQL 并不是为了完全取代 RDBMS，而是作为互补力量存在。业内普遍采用**混合持久化（Polyglot
Persistence）**架构：

1.  何时优先选择关系型数据库 (RDBMS)：

      - 业务核心涉及资金流转、订单交易，对数据一致性要求极高（如银行核心账务系统）。
      - 数据结构高度标准化，存在大量复杂的跨表关联分析需求。

2.  何时优先选择非关系型数据库 (NoSQL)：

      - 极端读写性能要求：如秒杀、热点缓存（选 Redis）。
      - 数据模型经常变动或结构复杂：如快速迭代的移动 App 业务数据、电商复杂 SKU（选 MongoDB）。
      - 海量非/半结构化数据写入：如日志采集、物联网设备时序监控（选 HBase、Cassandra、ClickHouse）。
      - 复杂关联关系挖掘：如社交好友推荐、资金链路穿透风控（选 Neo4j、NebulaGraph）。
      - 大语言模型与 AI 赋能：需要对文本或图像做语义向量检索（选 向量数据库）。
